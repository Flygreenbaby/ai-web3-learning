# Day 10 实践：Agent Session Key 策略设计

## 场景

> **"AI Agent 每小时自动更新一次 Sepolia 测试网上的 SimpleStorage 合约存储值（写入当前时间戳），无需用户每次签名确认。"**

## 1. 场景说明

| 项目 | 内容 |
|------|------|
| 角色 | AI Agent（自动执行者） |
| 目标合约 | SimpleStorage（Day 9 部署在 Sepolia） |
| 合约地址 | `0x849D7B802fC098d08633fc9425422929cA72F6f3` |
| 操作 | 调用 `set(uint256)` 写入当前时间戳 |
| 频率 | 每小时最多 1 次 |
| 网络 | Sepolia（Chain ID: 11155111） |

## 2. Session Key 权限配置

```
Session Key ID:        agent-simplestorage-001
签发者:                用户主钱包 (0x7b10...1746)
Session Key 地址:      [由智能账户生成的临时签名地址]
```

**允许范围（白名单）：**

```
┌─ 链限制 ─────────────────────────────────────┐
│  Chain ID:       11155111 (Sepolia)           │
│                                                │
├─ 合约白名单 ────────────────────────────────── │
│  0x849D7B802fC098d08633fc9425422929cA72F6f3   │
│  (SimpleStorage — 仅此一个合约)                │
│                                                │
├─ 方法白名单 ────────────────────────────────── │
│  set(uint256)    — 写入存储值 ✅ 允许          │
│  get()           — 读取存储值 ✅ 允许（view）  │
│  其他所有方法    — ❌ 禁止                     │
│                                                │
├─ 额度与频率 ────────────────────────────────── │
│  单笔 gas 上限:  100,000 gas                  │
│  最大交易次数:   24 次（≈1次/小时 × 24h）      │
│  最小间隔:       3,600 秒（1 小时）            │
│  ETH 转账额度:   0（禁止任何 ETH 转出）        │
│                                                │
├─ 时间限制 ──────────────────────────────────── │
│  生效时间:       2026-05-27T19:00:00Z          │
│  过期时间:       2026-05-28T19:00:00Z（24h）   │
│                                                │
└────────────────────────────────────────────────┘
```

## 3. 必须回到用户钱包确认的动作（红色区域）

以下操作 **不在 Session Key 权限内**，必须用户手动签名：

| 动作 | 原因 |
|------|------|
| 向非白名单合约发送交易 | 防止 Agent 调用未授权合约 |
| 调用 `set()` 以外的写方法 | 如合约升级后有 `destroy()` 等危险方法 |
| 任何 ETH / ERC-20 转账 | 防止资产流失 |
| 修改 Session Key 参数（延期、扩大额度） | 防止 Agent 自己给自己提权 |
| 部署新合约 | 超出 Agent 职责范围 |
| 跨链操作 | 不在授权链内 |

## 4. 撤销与审计

**撤销方式：**
- **主动撤销**：用户随时调用智能账户的 `revokeSessionKey("agent-simplestorage-001")`，立即失效
- **自动过期**：24 小时后 Session Key 自动失效，无需任何操作
- **次数耗尽**：24 次交易执行完后自动失效

**审计方式：**
- **链上记录**：所有通过 Session Key 发起的交易都记录在 Sepolia 上，可通过 [Sepolia Etherscan](https://sepolia.etherscan.io) 查看
- **筛选方法**：按合约地址 `0x849D...F6f3` + 方法签名 `set(uint256)` 过滤
- **事件日志**：智能账户每次执行 `set()` 可 emit 一个 `AgentAction(keyId, method, timestamp)` 事件，方便追踪
- **仪表盘（进阶）**：可用 The Graph 或 Dune Analytics 建立 Session Key 使用统计

## 5. 策略设计原则总结

```
🔴 红色（禁止）: Agent 不可触碰主私钥、不可转账、不可修改自身权限
🟡 黄色（需确认）: 超出额度/白名单/频率的操作 → 回到用户钱包
🟢 绿色（自动）: 在白名单内、限额内、时间内的 set() 调用 → Agent 自动执行
```
