# Week 1 Agent 实践：DAO 提案研究 Agent

**来源**: [Handbook — 智能体（Agent）](https://aiweb3.school/zh/handbook/ai/agent/)  
**完成日期**: 2026-05-24  

---

## 实践目标

做一个「DAO 提案研究 Agent」的最小版本，只执行只读动作，输出投票前检查清单。禁止投票、签名、发起交易。

---

## 1. 目标（Goal）

> 对任意一个 DAO 提案，Agent 自动执行只读研究流程，输出一份结构化的「投票前检查清单」。Agent 不投票、不签名、不发起交易。

**完成标准**：输出包含来源标注、正反理由、证据不足项、风险标记、人工检查清单五部分。

---

## 2. 工具（Tools）

Agent 拥有 5 个只读工具，每项按 6 问定义：

| # | 工具 | 输入 | 权限 | 副作用 | 日志 | 需确认 | 失败策略 |
|---|------|------|------|--------|------|--------|----------|
| 1 | `read_proposal` | `proposal_id` | 只读 | 无 | 记录时间 + ID + 响应码 | 否 | 超时重试 3 次；404 → 停止 |
| 2 | `search_discussions` | `proposal_id` 或关键词 | 只读 | 无 | 记录来源 URL + 命中数 | 否 | 超时重试 3 次；0 结果 → 标记「无讨论」 |
| 3 | `extract_arguments` | 讨论文本 | 只读 | 无 | 记录提取条数 | 否 | 文本格式异常 → 标记「无法解析」 |
| 4 | `detect_risks` | 提案正文 + 讨论 | 只读 | 无 | 记录风险类型 + 置信度 | 否 | 始终输出（无风险时输出「未发现明显风险」） |
| 5 | `check_completeness` | 所有已收集信息 | 只读 | 无 | 记录缺失项列表 | 否 | 始终输出 |

---

## 3. 状态（State）

外置记录以下字段，任何一步中断后可从 State 恢复：

| 字段 | 说明 |
|------|------|
| `proposal_id` | 当前分析的提案 ID |
| `proposal_title` | 提案标题 |
| `proposal_status` | 是否成功读取 |
| `discussion_sources` | 已检索的论坛 URL 列表 + 每条命中数 |
| `pro_arguments` | 支持理由（每条带来源标注） |
| `con_arguments` | 反对理由（每条带来源标注） |
| `missing_info` | 标记的缺失信息列表 |
| `risks` | 已识别的治理/资金风险 |
| `checklist_generated` | 检查清单是否已生成 |
| `step_log` | 每步时间、工具名、参数、结果摘要 |

---

## 4. 权限（Permission）

| 操作 | 模式 | 说明 |
|------|------|------|
| 读取提案 | 🟢 自动执行 | 只读，无风险 |
| 搜索论坛 | 🟢 自动执行 | 只读，无风险 |
| 提取总结信息 | 🟢 自动执行 | 只读，无风险 |
| 生成投票交易 | 🔴 需用户确认 | 写入操作，权限升级版才启用 |
| 发送交易 | 🚫 禁止 | 本 Agent 永远不执行 |

---

## 5. 停止条件（Stop）

任一触发，Agent 立即停止并报告原因：

| 条件 | 行为 |
|------|------|
| 提案不存在（404） | 停止 → "提案 #X 未找到，请检查 ID" |
| 论坛讨论完全缺失 | 停止 → 输出已有的提案分析，标记「无社区讨论」 |
| 发现高危风险（如合约漏洞） | 停止 → 优先输出风险报告，暂停常规流程 |
| 信息严重不足（缺 3 项以上关键信息） | 停止 → 输出"需补充信息"清单 |
| 用户主动拒绝 | 停止 → 记录拒绝时间 |

> ⚠️ 停止 ≠ 出错。停止是正常行为——Agent 诚实地告诉用户"我只能做到这里，下一步需要你决定"。

## 7. 权限升级版

从「只读研究」升级为「研究 + 受控写入」：

```
用户看完只读版检查清单后，如果决定投票：

Step 1  用户主动触发："授权进入写入模式"
        → 系统要求用户签名确认

Step 2  Agent 运行 Simulation：
        • 估算 gas 费用
        • 展示投票将消耗的代币/投票权数量
        • 标注是否有时间锁 / 委托冲突

Step 3  用户二次确认 Simulation 结果

Step 4  Agent 生成投票交易草稿（json/hex）
        → 不自动发送，交给用户手动签名后广播

全程记录日志：授权时间、Simulation 结果、用户确认时间、草稿 hash
```

**权限升级版新增工具：**

| 工具 | 权限 | 需确认 |
|------|------|--------|
| `simulate_vote` | 只读 | 否（但触发前要求用户授权） |
| `generate_vote_draft` | 写入（生成） | 是（Simulation 后二次确认） |
